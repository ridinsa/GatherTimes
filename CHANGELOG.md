# Changelog

## Unreleased
- Change: turning on "On-screen alert when ready" shows a sample alert. The "Test alert" button is removed.
- Change: options are grouped by what they do. Settings > General holds the alerts, the Hardcore health warning and the timer options; Display holds the window and map options (the tooltip switch moved here from Nodes); Tools holds the data actions (Reset timers, the new-session switch, and the debug report).
- Change: map pin options moved to Nav > Markers: right-click group menu and node offset while gathering.
- Change: one control per function. Removed the second "Auto-set arrow" checkbox (Nav > Route), the second "Clear waypoint" button (Timers), and the Timing "Current zone only" switch (it now follows the General zone switch, which also controls the map pins).
- Change: the General zone switch is renamed "Only show timers and pins of the zone I am in", since it controls pins as well as timers.
- Change: "Clear learned spawns" is now "Clear learned spawn points", and "Reset learned data" is now "Reset learned timings", so the two no longer share a name.
- New: the main window fades in over 0.2 seconds each time it is opened.
- New: minimized bar, "Always show minimized panel" option (Panel Settings, off by default, `miniAlwaysShow`). On: nothing is shown after a reload. Opening the addon (minimap button or `/gt`) brings up the window and the bar, and the bar stays on screen while the window and the other windows are open and after they are closed. Off: the bar appears only when the "-" button in the main window is left-clicked (it does not come back by itself after a reload).
- Change: the right-click panel for the "-" button is now titled "Panel Settings", and its "Minimized bar" caption is removed. The first row is the new option; the other rows are unchanged.
- New: minimized bar, "Bar opacity" slider (Minimize settings, 0-100 %, default 95 = the old look, `miniBgAlpha`). Only the bar and chip backgrounds (and the border) become see-through; text, chip contents and buttons stay solid. Follows skin changes.
- New: minimized bar, auto-fade (Minimize settings): "Fade in combat" (`miniFadeCombat`) and "Fade when mouse is away" (`miniFadeMouse`), both off by default, with a "Faded opacity" slider (`miniFadeAlpha`, default 30 %). The whole bar fades smoothly; the mouse over the bar, an open item dropdown or the open bags strip always show it fully. The bar size slider (`Bar size`) was already there.
- New: minimized bar, "Urgency colors" option (Minimize settings, on by default, `miniUrgencyColors`). The progress bar under a waiting chip is white above 60 s, yellow at 60 s or less and red at 15 s or less; READY chips stay green. The blink / fast blink is unchanged. The new texts are English only for now.
- New: minimized bar, "Compact chips" option (Minimize settings; off by default, `miniCompact`). A chip shows only the coloured edge, the short group label (G2) and the status / timer, so the chips are much narrower and many more fit before "+N more" (up to 48 chips are considered instead of 24). In "All checked" the colour tells the items apart. New `glabel` field on the table items (`UI\\MainTable.lua`, `UI\\MiniBar.lua`).
- New: minimized bar, "Hide idle groups" option (Minimize settings; off by default, `miniHideIdle`). Only groups that are running or ready get a chip; the "+N more" count only counts running / ready groups. When every group is idle the bar says "No groups running or ready." instead of the "no spots learned" note. The table in the main window is not affected. The new texts are English only for now.
- New: minimized bar, "Sort chips by urgency" option (right-click the "-" button > Minimize settings; on by default, `miniSortUrgency`). The chips are ordered by soonest ready: groups with a READY node first, then the shortest timer, then idle groups; ties keep the table's order. The sort happens before the 24-chip cut, so a group about to respawn is no longer hidden behind "+N more". Off: chips follow the table's order as before (`UI\\MiniBar.lua`, `UI\\Panels\\PanelMinimize.lua`, `Core\\Config.lua`). The new texts are English only for now (missing keys fall back to English).
- Fix: minimized bar chips are now a fixed width (not adaptive). The timer is no longer cut off on short group names (G1, G2 ...): the chip is sized for the widest name plus the widest status / timer at the current font style and size, and the text is never shrunk or clipped. Chips that do not fit become "+N more" (at least one chip is always kept when it fits). Changing the font style or text size in Settings > Look no longer leaves only "+N more" on the bar: the bar is laid out again right away with the new font (`UI\\MiniBar.lua`, `UI\\Style.lua`).
- New: minimized bar, "In bags" strip. While one item is picked, clicking the "In bags" text opens a strip to its left with the icon and bag count of each item that is ticked in the Nodes frame and listed there (only items with a count above 0 are listed, and the herb / ore filter and this-zone view apply; Thorium shows Arcane Crystal, the item it counts). The bags control is now a button, "<" with the count of the picked item when the strip is closed and ">" while it is open (the numbers are in the strip); it is lit while the strip is open. Right-click it to restore the window. Before the button, the icon of the item picked in the bar's dropdown (the item the count is for; Thorium shows Arcane Crystal), and it follows the dropdown. It is hidden while the strip is open.; click it again to close the strip and show the number again. It closes with the bar. When the strip needs room the group chips narrow first, their name and status shrinking to fit, and only a chip narrower than 60 px is left out as "+N more". The bar has no tooltips except the session summary on the gold text (`UI\MiniBar.lua`).
- Fix: 47 texts that still showed in English in every language are now translated in all 11 language files: the minimized bar (Minimize / Restore), the Session summary window, spot Export / Import, the Debug report window, zone yields (/gt yield), several Settings, Timing and Nodes tooltips, the Frame skin / Font labels, the slash-command help lines and "Random colour".
- New: minimize button. The "-" button in the title bar (left of "?") hides the main window and shows a one-line bar docked along the top of the screen, like Titan Panel (`UI\MiniBar.lua`). On the left, an item dropdown (the same choices and the same pick as the main window, the two stay in step) followed by a chip per group in the same order and colours as the table: a coloured edge in the item's colour, the group name, its status and timer, and a thin bar along the bottom that is full while the group is ready and drains as the respawn gets closer; the chips have one fixed width (sized for the longest group name and the widest status + timer, e.g. "Waiting  88:88"), so nothing moves or resizes while the timers tick. On the right, aligned to the right edge: the bags (while one item is picked), the session gold, and the "+" button. Groups that do not fit become "+N more" (24 chips at most). No zone or realm. While the bar is shown the game's top frames (player, target, focus, party, minimap, buffs, objective tracker ...) are moved down under it, and they go back to where they were when the window returns (`UI\BarDock.lua`): only frames anchored to the top of the screen are moved, a frame the game re-anchors by itself is shifted again, nothing is moved in combat (done when combat ends), and everything is put back at logout / reload so the game does not save a shifted position. `/gt dock` switches the pushing off (the bar then just covers the top). The bar is drawn in front of other windows (strata DIALOG). "+" or a right-click restores the window; opening the window another way (`/gt`, the minimap button) also puts the bar away. `/gt min` toggles it. The state is saved (`_ui.minimized`, `_ui.barDock`), so a reload keeps the bar. The bar is no longer draggable (old `barPoint`/`barX`/`barY` values are ignored). The new texts are English only for now (missing keys fall back to English).
- New: persistent zone yield totals. `/gt yield` shows the ten zones with the most recorded gathers, per-resource item quantities, drop counts and average quantity per gather; `/gt yield current` limits the report to the current zone. Loot-window/chat duplicates are reconciled, extra node loot is tracked separately, and damaged saved entries are cleaned on load.

## 0.22.0 (patch 3)
- Fix: timers are no longer deleted without warning. `GT.NormalizeGroupTimers` (regroup, group mode switched on, spot menu, Nodes panel) used to drop every timer beyond a group's capacity (default 1) even while it was still running. It now drops an extra only once it has run out; running extras stay and keep their own position (`Gathering\Learn.lua`).
- Fix: `sp.nexts` no longer grows without limit. Each spot keeps its 8 strongest "went there next" followers (`GT.NEXTS_MAX`, `GT.TrimNexts`, `Core\Util.lua`); the weakest are dropped, equal counts by lowest spot id, and the follower that was just counted is never the one dropped. `RegisterLoot` trims on every count; `GT.PruneSpotRefs` cuts files from older versions at load and drops counts that are not positive numbers.
- Fix: settings have limits. `speed` 1..40 yd/s (0 made every "Leave now" alert fire at once and divided by zero in the routes), `routeRange` 10..1000 yd, `leaveEarly` 0..300 s, respawn time per item 30 s..2 h (`GT.TIMER_MIN/MAX`, `GT.ClampTimer`). Applied at load, in the Nodes panel minutes box (which now shows the value that was taken) and when a learned time is applied. Missing, non-numeric or NaN values fall back to the default; an invalid saved timer is dropped.
- Change: `_hasAlerted` and `_leaveAlerted` stay in the saved file ON PURPOSE (a timer that already alerted must not alert again after a quick relog or /reload). This is now written down in `Core\Events.lua` (PLAYER_LOGOUT) and `GT.SanitizeDB` keeps only the value `true`.
- Fix: Hardcore tagging when `C_GameRules.IsHardcoreActive()` is not ready at load. `GT.SanitizeDB` remembers the realm tag it used (`GT.realmAtLoad`); at PLAYER_ENTERING_WORLD `GT.RecheckRealm` compares it with the tag now and, if it differs, sorts the timers again (timers parked under the Hardcore tag come back). A timer parked this way also loses its map label (`GT.MigrateRealm`).
- Not changed: the rounding to 5 decimals. Whether the game writes 16 or 17 significant digits decides how much it saves; compare the size of `GatherTimes.lua` in SavedVariables before and after one login.
- Tests: group extras, nexts limit (counts, ties, new follower, old file), setting limits, alert flags, late Hardcore flag (5 new tests).

It now calls the library's public `SetMinimapObject`, which ends in a forced full layout, in the same frame as the resize (no more 0.2 s wait). Several changes inside one frame (a slider drag) are laid out once, plus once more on the next frame; the label restyle keeps its 0.2 s debounce. The old function names are still tried on a library revision that has no `SetMinimapObject` (HUD\HUDPins.lua). GatherMate2 and TomTom pins share the same library, so they follow too.

Settings > Tools > "Export my spots" (or `/gt export`) shows them as one line of text to copy; "Import spots" (or `/gt import`, or `/gt import <text>`) takes such a line. Exported: spots you learned and imported spots you have gathered at; only item, zone and position travel (no timers or counts). Imported spots arrive like GatherMate2 ones (`imported`, no hits), so they never push out a spot you learned and the first loot next to one snaps onto it; a spot within the merge radius of one you have counts as already known. The text carries a spot count and a checksum: a paste that was cut off or edited is refused as a whole. Spots of an item this version does not know, or outside 0..1, are skipped and counted. Line breaks and spaces added by a chat client are ignored (Gathering\Share.lua, Core\Core.lua, UI\Panels\PanelSettings.lua, help text).

- Change: "standing near a spot means it is empty" (Settings > Timing > Detect empty nodes) is stricter, because it could mark spots empty by mistake and skew routing. It now counts only after you walked TOWARD that spot (the distance kept shrinking, within 40 yards, in the last 20 seconds), then stopped within 8 yards and stayed put (moving more than 3 yards starts the wait again), for 12 seconds (was 8). A cast, combat, AFK, resting, an NPC window, or a loading screen resets it; a cast alone no longer starts a wait. Standing next to a spot after logging in, dismounting or waiting for a group no longer counts. The time is a constant in the code, not a saved setting, so everyone gets 12 seconds with the update and no settings migration is needed; the on/off switch you chose is kept (Gathering\Learn.lua `GT.CheckDwell`).

No character or realm name and no positions are in it. A part that cannot be read is replaced by a note and the rest is still produced (Core\Report.lua).
- Packaging: GitHub workflows in `.github\workflows\`. `ci.yml` (every push and pull request): syntax check of every Lua file and the tests on Lua 5.1 and 5.4, then a dry-run build of the release zip kept as a build artifact. `release.yml` (tag `vX.Y.Z`): checks the tag against the `.toc` version, runs the tests, builds the zip with the BigWigs packager and attaches it to a GitHub release. `RELEASING.md` has the steps; `.pkgmeta` leaves `.github` and `RELEASING.md` out of the zip.
- Tests: the stricter dwell rule (never counts without a walk toward the spot, 11 s is not enough and 12 s is, once only, walking past, moving while waiting, cast / vendor window / switch off) and the debug report.
- Version: 0.22.0.
